# 연세 BK21 대학원생 워크숍 웹페이지 PRD

Oct 20, 2026 · @김영광

## 개요

워크숍 웹페이지(LMS)의 목표를 '연구 설계도 작성'에서 \*\*'나의 핵심 연구 질문 찾기'\*\*로 좁히고, 4시간 안에 끝나도록 단계를 줄인다.

- **출처:** 2026-10-20 학술정보서비스팀·모두의연구소 협의 녹취록(56분, 회의 중간부터 녹음). 자동 전사본이라 `[?]`·`[불명]` 구간은 해석을 거쳤다.
- **대상 산출물:** 대학원생 워크숍 LMS 웹페이지의 단계 구성, 프롬프트, 안내 문구, 내려받기 패키지.
- **보안:** 고객사 내부 논의가 포함돼 있어 외부 공유용이 아니다.

### 워크숍 흐름 (변경 후)

연구 대상 정하기 → 검색식으로 학술 DB 검색 → 메타데이터 CSV 내려받기·통합 → 연구 지형도 그리기 → 핵심 논문 고르기·뼈대 파악 → AI 역질문으로 연구 질문 모으기 → (선택) 질문으로 지형도 다시 그리기 → 핵심 연구 질문 정하기

## 목표와 성공 지표

참여자가 4시간 안에 학술 DB와 AI로 자기 핵심 연구 질문을 구체화하고, 그 방법을 스킬로 가져가 집에서 100건, 1,000건 규모로 다시 돌릴 수 있게 한다.

| 지표 | 기준 | 측정 방법 |
| --- | --- | --- |
| 핵심 질문의 변화 | 사전 질문 대비 사후 질문이 구체화됨 | 사전·사후 설문의 핵심 질문 비교 |
| 시간 내 완주 | 연구 지형도까지 약 2시간, 전체 4시간(버퍼 30분 포함) | 강사 관찰, 단계별 진행 체크 |
| 사용량 한도 내 완료 | 제공 계정(Sonnet 5.5) 5시간 한도 안에서 전 과정 완료 | 드라이런(이공계·인문 각 1건) 토큰 측정 |
| 가져갈 산출물 | 내 연구 질문 패키지 + 단계별 스킬 내려받기 | 내려받기 완료 여부 |

**범위 밖:** 연구 설계도 작성, DBpia·국내 연구 확인, 검색 결과 전체(수백\~천 건) 분석. 전체 분석은 샘플과 방법만 제공하고 수업 후 개인 과제로 둔다.

## 사용자와 역할

웹페이지의 주 사용자는 이공계·인문계가 섞인 대학원생이며, 강사는 분야별로 나눠 지도한다.

| 역할 | 누구 | 웹페이지에서 하는 일 |
| --- | --- | --- |
| 참여자 | BK21 대학원생(선착순, 인원 상한 미정) | 단계별 입력 → 프롬프트 복사 → Claude 실행 → 질문 선택 → 패키지·스킬 내려받기 |
| 주강사 | 이공계 담당 | 전체 진행, 이공계 좌석 지도, 11/4 강의 화면 녹화 |
| 보조강사 | 인문계 담당 | 인문계 좌석 지도 |
| 운영 | 연세대 학술정보서비스팀 | 신청·설문 운영, 계정 사전 접속, 추가 결제 검토 |
| 제작 | 모두의연구소 | 교안·프롬프트·스킬 제작, 드라이런, 영상 후처리 |
| 자문 | 담당 교수 | 핵심 질문 구체화 노하우 제공 |

좌석은 이공계와 인문계로 나눔다. 참여자 화면에는 자기 분야를 고르는 선택지가 있으면 필터·예시 안내에 쓸 수 있다(제안).

## 기능 요구사항

가장 큰 변화는 세 가지다. 핵심 논문을 피인용 상위 20건으로 자르지 않고 참여자가 고른 기준으로 WoS·Scopus 각 30건을 모아 통합한다. 질문 훅은 Step 1\~3에서 1회로 줄이고 Step 4에 몰아준다. DBpia와 국내 연구 단계는 빠진다.

모든 항목은 워크숍 전에 반영한다. 10월 20일 추가 결정으로 ‘선택’ 항목(D-11 지형도 질문 노드, I-4 발표용 패키지 화면)은 빼고 ‘권장’ 항목은 필수로 올렸다.

| D-9 | 지형도는 통합 목록으로 연구 묶음을 만들고, 내 키워드와 가장 가까운 묶음을 참여자가 고른다. 묶음별 평균 피인용은 참고값으로 표시한다. | 필수 |

## 비기능 요구사항 및 제약

가장 큰 제약은 사용량이다. 제공 계정 1개로 4시간 내내 끝까지 가야 하고, 막히면 수업이 멈춘다.

| 항목 | 요구사항 |
| --- | --- |
| 모델 | Sonnet 5.5 고정 |
| 사용량 한도 | 5시간 한도. 수업 당일 10시에 계정을 미리 접속·대화 1회해 15시에 리셋되게 한다. 사람 손 없이 자동으로 할 수 있으면 더 좋다. 당일은 참여자가 계정을 계속 쓸 수 있어야 한다. |
| 사용량 검증 | 서브에이전트 드라이런(가상 학생이 교안을 처음부터 끝까지 수행)을 이공계·인문 각 1건 돌려 토큰 소모를 잰다. 문제가 있으면 워크숍 전에 해결한다. |

## 미결 사항 및 확인 필요 질문

아래 항목은 회의에서 방향만 나왔거나 답이 없다. 앞의 다섯 개는 LMS 수정 전에 정해야 한다.

- [ ] 6-2(두 번째 앵커)·6-3(주장 설계표)을 삭제할지, 선택 단계로 둘지? 목표가 ‘연구 설계도까지 가지 않음’이라 삭제 쪽이 자연스럽다.
- [ ] 핵심 논문 선정에서 정량(피인용·JIF)과 정성(주제 적합도)을 어떻게 섞을지. 회의에서 ‘정반합’을 고민하기로 했다. 피인용 0건 논문 제외 여부도 포함(최신 논문은 0건일 수 있음).
- [ ] 자료 유형 선택지 목록: 학술정보서비스팀이 업적 평가용 분류를 제공하기로 했다.
- [ ] WoS 30 + Scopus 30 → 통합 50건 이하가 Sonnet 5.5 한도 안에서 되는지: 드라이런 결과로 확정한다.
- [ ] Step 1에서 검색식을 어디까지 남길지. 회의 발언 ‘검색식은 2단계부터 시작해도 좋다’를 건수 확인용 단순 검색만 남기는 것으로 해석했다.
- [ ] 운영비로 추가 사용량을 결제할 수 있는지(담당자 확인 예정).
- [ ] 계정 사전 접속을 자동으로 할 방법. 안 되면 운영진 약 10명이 1인 5개씩 접속하는 안.
- [ ] 사전 설문 문항 확정, 사전 질문을 LMS에 어떻게 넣을지(참여자가 Step 1에 직접 입력 또는 별도 칸).
- [ ] 우수 사례 발표 인원(분야별 1명 또는 2명)과 선정 방식.
- [ ] 교수 노하우 원고와 ‘5시간 안 AI 사용량 실험’ 문서를 언제 받는지.
- [ ] WoS 무료 Starter API: 존재는 미검증이고 이번에는 반영하지 않는다. 겨울 교육 때 검토.
